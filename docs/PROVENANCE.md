# Provenance

Where each fact the client relies on comes from, one line per fact. The
format specs themselves are under [client/docs/formats/](../client/docs/formats/).

## Packs and the `.ipa`

- read from the user's own files: the `.ipa` is a plain ZIP holding the packs as `Payload/<app>/<pack>.bin`.
- read from the user's own files: packs are ZIPs whose local headers start `GBMP` (`0x504D4247`) instead of `PK\x03\x04`; the central directory (46-byte entries) and end record (22 bytes, at the very end, no comment) are standard. Spec: `client/docs/formats/pack.md`.
- read from the user's own files: packs use only methods 0 (stored) and 8 (raw DEFLATE); sizes fall back to the central directory when flag bit 3 is set or the local sizes are zero. Spec: `client/docs/formats/pack.md`.
- read from the user's own files: names disagree in case between packs and the data that refers into them, so lookups are by lowercased name.
- read from the user's own files: each `.bdae` in `res.bin` is a ZIP holding `little_endian_not_quantized.bdae` and `version.nfo`.
- read from the user's own files: the pack names in `Library.ts` (`res.bin`, `res_t.bin`, `tables.bin`, `sound.bin`, `model_phy.bin`, `conf.bin`, per-map `<map>.bin` and `<map>_layer.bin`).

## Sound

- read from the user's own files: every file in `sound.bin` is RIFF/WAVE, coded as IMA ADPCM (`0x11`), Microsoft ADPCM (`0x02`) or 16-bit PCM; the ADPCM block layouts and tables are the public IMA and Microsoft specifications. Every file decodes, checked in `realPacks.test.ts`. Spec: `client/docs/formats/sound.md`.
- read from the user's own files: `c_sound` column 1 is the count of numbered files (it matches what the pack ships), 3 the file, 4 a volume, 7 a `c_sound_bank` key; column 2's bit 1 is set on exactly the music rows, bit 2 on sounds that happen somewhere and never on interface, music or ambience rows, bit 4 on music, ambience, running objects and `…_loop` files. Numbered files are `_1` to `_n` of one name, a few rows leave off `.wav`, and some families skip a number.
- own reading of the user's files: `c_sound` column 6 (10 to 150 on 40 rows) as how far the sound carries; column 2 bit 8 (mostly on creature, weapon and footstep sounds) as "vary each play"; `c_sound_bank` column 2's low 16 bits (1 to 8, beside names like `NPC_AGGRO` and `NPC_HURT`) as how many play at once.
- read from the user's own files: `sound_solution` columns 1-14, each named by the files its ids point at across the rows (idle, greeting, attack, jump, aggro, drink, die, eat, hurt, shout, hello, bye, cry, critical); the last `creaturemodeldata` column is a `sound_solution` key, and the set's description matches the model's; the zone's music and ambience are the two `u` columns ahead of the first string in `zones`, holding ids of `m_…` and `sfx_amb_…` files; `ZoneSpecialMusic` pairs a zone with an arena's or region's `…_combat` piece; `c_spellvisualstate` column 8 holds ids of `sfx_skill_…` and weapon files.
- read from the user's own files: `.phy` flag bit `0x400` is on the collision of bridges, docks, wharves, piers, wooden plates and shelves, inns and boats, and on no stone or earth model; read as a wooden surface.
- read from the user's own files: which item class, sub-class and worn slot holds what, from the item names in each group (worn slot 1 head … 19 off hand; armour sub-class 1 cloth, 2 leather, 4 mail; consumable sub-class 1 potions, 3 scrolls, 4 food, 9 spell books; class 6 materials, 7 handbooks).
- read from the user's own files: the weapon sounds come in families by file name — `sfx_weapon_edge_…`, `blunt`, `dagger`, `fist`, `parry`, `arrow`, `wand` — each with a swoosh, a flesh impact, a critical impact and a block; 1.1.4's Mendel models name voice set 0 and the build ships no Mendel voice files.
- own choice: a purchase plays `sfx_ui_pickup_money` rather than `sfx_ui_shop_deal`.
- read from the user's own files: the talent card (`dlgTalentDesc`) carries a confirm strip `panelAddPoint/panelConfirm` (`btnConfirm`, `textConfirm`) under its points row `panelAddPoint/panelAdd`. Own choice: an aura card wears that strip as Cancel for the hero's own ride, the one aura the player can take off.
- read from the user's own files: the goods card (`dlgGoodsDesc`) carries a shop strip `panelBuy` — the control `group/btnBuy`, the label `textbuy` and a price of `textGold`/`textSilver`/`textIron` beside `iconGold`/`iconSilver`/`iconIron` — with a second row (`group/btnCompare`, `group/panelTryOn`) and other currencies (`priceBusiness`, `storestone`) this client hides.
- own choice: every rule for *when* a sound plays and how it is heard — the music timetable and its numbers, which zone's music applies, the reach, pitch spread and bank behaviour, footstep timing, how often bodies speak, which weapon takes which family, the borrowed voice for a race with none, which item takes which equip and pick-up sound, click sounds, and fight music during a duel. See `docs/BEHAVIOUR.md`.

## Tables (`.tbl`)

- read from the user's own files: the 44-byte header that opens with `FTABLE` — row count +12, column count +16, row keys +20, format string (one letter per column) +24, rows +28, row stride +32; a string cell's offset counts from the start of the file. Spec: `client/docs/formats/ftable.md`.
- read from the user's own files: format letters and widths k/u/i/f 4, h 2, c 1, s 6, the only letters any table in either of the user's builds uses (a `uint32` offset and an `int16` length counting the closing zero); the widths sum to the stride in every table.
- read from the user's own files: strings are UTF-8 or single-byte windows-1252.
- read from the user's own files: the tables carry no column names, so the column indices in `tables.ts` and `localTile.ts` are positions in the user's tables, checked against each table's format string at load and against the user's rows in `realPacks.test.ts`.
- read from the user's own files: `staticobject_proto` column 19 is the festival id, and its non-zero values are ids from `festival.tbl`.
- read from the user's own files: a zone's sky is the table's only run of six string columns — the dome model, a horizon "hill" model, the sun or moon texture, an empty field, a halo texture, an empty field — starting at column 20 in 1.1.4 and 22 in 2.2.0 (2.2.0 adds two floats ahead of it); the zone's map glyph is the first string column after the run, 32 and 34. `0` or a bare directory means none. Checked in `realPacks.test.ts`.
- read from the user's own files: `map_info` name and `.wld` path are the first adjacent pair of string columns; `staticobject_spawns` has one scale float at column 11 in older builds and three from 1.1.4.
- read from the user's own files: the spell visual chain links — `c_spellvisual` columns 1-7 hold `c_spellvisualstate` ids and column 8 a `c_spellvisualeffect` id; `c_spellvisualstate` column 1 holds a `c_animationdata` id and columns 2-7 `c_spellvisualeffect` ids; `c_spellvisualeffect` column 2 is a `.beff` path and column 6 a percentage scale; `c_animationdata` column 1 is a clip name and column 2 a 0/1 loop flag set on the looping clips (stun, aim, gather, hold).
- own reading of the user's files: what each of the seven phase columns is, from the clips and file names its rows name — 1 short gather clips and in-hand files (opening), 2 looping gather clips on spells with a cast time (wind-up), 3 release and strike clips and "release" files (release), 4 hurt clips and "hit"/"pow" files (impact), 5 buff, debuff, stun and sleep loops (lasting), 6 files in the last effect column placed on the ground (area); column 7 is set on seven rows, is read and not shown.
- own reading of the user's files: the six effect columns as body anchors — sleep and stun files in the first (overhead), hit and aura files in the second (chest), ground and footprint files in the third (feet), in-hand files in the fourth and fifth (the fourth, used about three times as often, taken as the right hand), area files in the sixth.
- observed in play by the owner: the node each anchor hangs off (`Dummy_Head_Effect-node`, `Bip01_Spine`, `Dummy_R_Hand-node`, `Dummy_L_Hand-node`); read from the user's own files: those names are nodes in the user's models.
- own reading of the user's files: `c_spellvisualeffect` column 7 as placement — 0 on four rows in five (rides its anchor), 2 on "pow" and sparkle files (a one-shot burst), 3 on ground, footprint and area files (dropped in the world), 1 on breath, wave and aim files (rides the body, own choice: the chest), 4 on one parry row (treated as 0).
- own reading of the user's files: `c_spellvisualstate` column 10 is 0, 1 or 2; 2 is taken as a clip that takes the whole body. Column 8 is a `c_sound` id, played with the phase; column 9 (a 0/1 flag on four rows, taken as camera shake) is read and not used.
- own reading of the user's files: `c_spellvisual` column 9 is set only on melee skills; its high byte is 0 or 2 and its low byte 1-9, taken as the blade streak texture number. Own choice: the streak plays with the release, whatever the high byte says; every visual with a non-zero high byte has its release phase in column 3.
- own reading of the user's files: `c_spellvisual` column 10 is 100 on almost every row and 200-500 on a few heavy melee strikes, taken as the milliseconds between the swing and the impact; `c_spellvisualeffect` column 9 is 0-6, taken as the projectile count (0 read as 1).
- read from the user's own files: `spell_new` columns — skill set 1, name string 5, rank 6, description 7, icon 10, cast time 16, visual 26; column 25 is above 0 on a mount, and column 43 holds flags whose bit `0x4` marks a spell that is never cast.
- shared with this project's server, and checked against the user's own files: `spell_new` column 17 is the cooldown in milliseconds (999 ms to an hour), column 21 the maximum reach in world units (up to 110) and column 41 the power cost (on nearly every castable spell, up to about 2,400), the same in 1.1.4 and 2.2.0. Checked in `realPacks.test.ts`.
- read from the user's own files: the spell card (`dlgSpellDesc`) draws its own picture beside each of its four short lines — a droplet by `text01`, a ruler by `text02`, a clock by `text03` and a turning arrow by `text04` — taken as cost, reach, cast time and cooldown.
- read from the user's own files: the item and spell cards carry `lineTop`, `lineBottom` and `scrollBar`, the same parts the talent card draws only while its words run on.
- read from the user's own files: `items.tbl` sub-class numbers grouped into kinds in `assets/heldKinds.ts` — weapons 0-2 one-handed swords, axes and maces, 3 daggers, 4 knuckles and katars, 8-10 two-handed swords, axes and hammers, 11 staves, 12 spears, 16 bows, 17 crossbows, 20 wands; armour 5 shields, 6 off-hand rods and totems — checked against the item names and item model file names in 1.1.4 and 2.2.0. No item in either build uses weapon sub-classes 5-7, 13-15, 18 or 19.
- read from the user's own files: every playable character's combat clips come in the families `1h`, `2h`, `dagger`, `polearm`, `stave`, `bow`, `crossbow` and `thrown` (plus `combat_block_shield`); three families have an off-hand swing, `combat03_1h`, `combat03_dagger` and `combat03_stave`, in all 8 race folders in both builds, and no family `gun` exists.

- observed in play by the owner: blades, daggers, bows, crossbows and wands rest where their slot keeps what it holds (`SLOT_REST`) — the hip of its side for the main and off hand, `Dummy_R_Back` for the two-hand and ranged slots; a bow or crossbow in the ranged slot is drawn in the left hand, everything else in its slot's hand. ## Interface text

- read from the user's own files: the `EN.bar` layout in `uiStrings.ts` — a boundary count, two padding bytes, the group boundaries, then groups of a count, offsets and zero-terminated words.
- read from the user's own files: SWF instance names, looked up at runtime.
- read from the public SWF specification: tag 83 is the fourth shape tag, with edge bounds, a flags byte and two-byte line style flags.
- read from the public SWF specification: DefineFont2 (48) and DefineFont3 (75) open with a 16-bit font id, two flag bytes and a length-prefixed name; DefineEditText (37) carries the id of the font it is set in when its has-font flag is set.
- read from the user's own files: the interface movies embed no glyph outlines; each names its typefaces, and the `.app` bundle ships TrueType files beside the packs whose own family names (the `name` table, ids 1 and 16) match the two names the movies' text fields use most. In 1.1.4 about 94% of fields use one name and about 6% the other, mostly centred captions; a third name used on four fields ships no file. No typeface in the movies sets the bold flag.
- read from the public OpenType specification: the table directory and the `name` table layout read by `typeface.ts`.
- own choice: the body face is the name most text fields use and the title face the next most used, each paired with the shipped file of the same family; a title name with no file is left unpaired rather than given the next name down.

## Models (`.bdae`)

- read from the user's own files: the 60-byte header — `BRES`, `0xFFFE` at +4, version at +6, header size at +8, file size at +12, string table at +28, model info at +32, data at +40. Spec: `client/docs/formats/bdae.md`.
- read from the user's own files: where each list starts in model info (animations +36, animation store +48, textures +76, materials +92, geometries +100, controllers +108, node trees +148) and the record sizes (texture 20, material 36, parameter 24, geometry 16, part 56, controller 12, node tree 16, node 80, instance 8, animation 32, sampler 28, channel 16). Spec: `client/docs/formats/bdae.md`.
- read from the user's own files: the node record layout (id, name, sid, translation +12, rotation +24, scale +40, visible +52, children +56, instances +64), instance types 2 (controller) and 3 (geometry).
- read from the user's own files: parameter type 11 is a 2D sampler, reached through sampler and surface records to an image index, -1 meaning none.
- read from the user's own files: the skin, morph, animation, sampler, channel and segment record layouts listed in `client/docs/formats/bdae.md`.
- read from the user's own files: source type 1 (unsigned byte) and 6 (float); attribute type 6 (float) and four normalised bytes for the vertex colour.
- read from the user's own files: segment source offsets are self-relative.
- read from the user's own files: animation channel kinds 1-5, 7-10 and 14 (`skeletonWire.ts`), checked by the part of the body each moves; no model in either build uses kinds 6 or 11-13, so they are skipped as unknown.
- read from the user's own files: stored quaternions are conjugated.
- read from the user's own files: material and effect family names (for example `unlit_textured_solid-fx`) are strings in the user's models.
- read from the user's own files: the church's window shafts are the meshes `light`, `light01`–`light03`, wearing the ordinary `unlit_textured_blend_2sides` material with no parameter apart from the walls' (texture and technique only); across every scene model in 1.1.4 the blended meshes named `light…` are only shafts in churches and castles, and `Genera_sunshine` is only on shafts. Their vertex colour darkens along each shaft (down to 28 of 255). Judged by the owner in this client, with every blended material switched to additive: the shafts look right that way. Own choice: blended groups on those meshes, or wearing a `sunshine` texture, draw additive (`isLightShaft`). Checked in `realPacks.test.ts`.
- own choice, tuned by eye: animation key times are played at 30 ticks per second.

## Textures (PVR)

- read from the user's own files: the 52-byte PVR v2 header — header size +0, height +4, width +8, mip level count +12, flags +16 whose low byte is the format, 24 (2 bpp) or 25 (4 bpp), and whose bit `0x8000` means alpha, `PVR!` at +44 — with mip levels stored largest first, back to back. Spec: `client/docs/formats/pvr.md`.
- read from the public PVRTC description: block word order, colour A/B bit layouts, modulation weights {0, 3, 5, 8} and {0, 4, 4, 8} with punch-through at value 2, bilinear colour upscaling and Z-order block layout. The block-order function is written from the definition of Z-order; for this function, no third-party code is used.

## World tiles

- read from the user's own files: tiles are 64 units a side (`TILE_SIZE`); `.itm` positions fall inside that square.
- read from the user's own files: tile file names use four characters per coordinate (`0017_0012`, `-025_-016`).
- read from the user's own files: the `AITM` header (24 bytes) and 56-byte (stamp 3) or 64-byte (other stamps) records — model index +12, position +16, rotation +28, scale +44 — and the path table after them. Spec: `client/docs/formats/terrain.md`.
- read from the user's own files: the `ATIL` layout — 24-byte header, 64 chunk headers of 12 bytes, 65 x 65 `int16` heights in hundredths, RGB565 tints, three-byte normals, then the texture list. Spec: `client/docs/formats/terrain.md`.
- read from the user's own files: -1000 in every height sample means an empty tile.
- read from the user's own files: chunk flag bit 16 is water and bit 17 a hole; water level and three texture indices follow, -1 meaning none.
- read from the user's own files: masks and shadow maps are headerless 256 x 256 8-bit grids in `<map>_layer.bin`.
- read from the user's own files: nine buildings ship `<name>_inside.bdae` beside `<name>.bdae` in `res.bin`, and seven of those shells repeat inner walls, floors and beams that the interior draws again in the same plane, lit differently. The inn's shared walls lie within 0.0003 units of each other; a rug laid on its floor sits 0.005 units or more above it. The inn is checked in `realPacks.test.ts`.
- own choice: a building placed from a tile's `.itm` gets its `_inside.bdae` placed with it at the same spot, and the shell drops every face its interior covers completely within 0.002 units, facing the same way (`interiorCompanion.ts`).
- own choice: the resident ground window follows the player once they stand more than 12 units outside its middle tile on either axis, on the same frame at any distance (`FOLLOW_SLACK` in `TileStreamer.ts`).
- own choice, tuned by eye: layer 0 blends by the mask's red channel, layer 1 by green, and the shadow map rides in blue with 0 lit and 255 dark.

## Collision (`.phy`)

- read from the user's own files: a `.phy` sits at its model's path with the extension swapped, in `model_phy.bin` (2.2.0) or `tables.bin` (1.1.4).
- read from the user's own files: a block count, then blocks of an `int32` type and a 32-byte body — 2 wall, 3 box, 4 cylinder and 7 mesh; no file in either build uses any other type, 1 included, so any other ends the list; primitives hold flags, a turn, a centre and half extents; meshes hold flags, a position, half extents, vertex and face counts, then 12-byte vertices and 8-byte faces of four indices. Spec: `client/docs/formats/phy.md`.
- read from the user's own files: the files store the vertical axis third, so coordinates turn from `(x, y, z)` to `(x, z, -y)`.
- read from the user's own files: only flag bits 0, 1, 10 and 14 are ever set.
- own choice: blocks with flag bit 0 or 1 set are left out of solid collision.
